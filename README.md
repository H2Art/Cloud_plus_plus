# ☁️ Cloud++

**Личное облачное хранилище для одного пользователя.**
Маленький C-бэкенд, один статический бинарник, обычные файлы на диске.

## Возможности

- 📁 **Папки**: создание, вложенность, удаление
- ⬆️ **Загрузка** перетаскиванием (drag & drop) или через диалог, потоком, без буферизации в памяти
- ⬇️ **Скачивание**: файлы отдаёт напрямую nginx, бэкенд в этом не участвует
- 🧹 **Чистая загрузка**: данные пишутся во временный файл и публикуются только при получении всех байт, обрыв не оставляет мусора
- 🔒 **Защита**: HTTPS, пароль на всё, защита от выхода за пределы хранилища, CSRF-заголовок, строгий CSP
- 💾 **Бэкапы**: ежедневные снимки через restic и копия на домашний компьютер
- 🪶 **Лёгкий**: укладывается в 1 ГБ RAM, без базы данных, без Docker

Ограничения версии 1.0: один пользователь, файл до 500 МБ, хранилище 2 ГБ, перезапись существующих файлов запрещена.

## Как это устроено

```
Браузер ──HTTPS──▶ nginx ──▶ C-бэкенд (127.0.0.1:8080)
                     │            │
                     │            ▼
                     └──────▶ /srv/storage/files   (ext4 в loop-образе, 2 ГБ)
                   скачивание
                   и статика
```

| Компонент | Что делает |
|---|---|
| **nginx** | HTTPS (самоподписанный сертификат на IP), basic auth, отдаёт `/dl/` и `/static/` |
| **Бэкенд** | список файлов, создание папок, удаление, приём загрузок (Mongoose 7.24) |
| **Хранилище** | обычные файлы в loop-образе `ext4`, у него своя квота |
| **Фронтенд** | htmx 2.x и небольшой `app.js`, страницы отдаёт бэкенд |

Бэкенд не имеет собственной авторизации и принимает соединения только с `127.0.0.1`, наружу его выставляет nginx.

### Маршруты бэкенда

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/` | страница приложения |
| GET | `/list?p=` | содержимое папки |
| POST | `/mkdir` | создать папку |
| DELETE | `/rm?p=` | удалить файл или папку |
| POST | `/upcheck` | предпроверка загрузки (размер, место, имя) |
| PUT | `/up?p=` | потоковая загрузка файла |

Изменяющие запросы требуют заголовок `HX-Request: true`.

## Структура репозитория

```
src/core/     логика без HTTP: пути, файлы, листинг, квота, загрузка, очистка
src/http/     маршруты, поток загрузки, склейка с Mongoose
src/vendor/   Mongoose 7.24
static/       app.js, app.css, htmx.min.js
tests/        тесты на C (core, http) и на Node (js), свой мини-фреймворк
deploy/       развёртывание: скрипты, systemd, nginx, бэкапы
```

Подробности и принятые решения лежат в [`NOTES.md`](NOTES.md).

## Быстрый старт (локально)

Нужны `gcc`, `make` и, по желанию, `node` (для JS-тестов).

```sh
make test                      # тесты (ASan + UBSan)
make build                     # бинарник в build/release/cloud

mkdir -p /tmp/cloud-data
build/release/cloud --root /tmp/cloud-data --static static --serve-downloads
# откройте http://127.0.0.1:8080
```

Параметры запуска:

| Флаг | Значение |
|---|---|
| `--root DIR` | каталог хранилища (обязательный) |
| `--static DIR` | отдавать `/static/` самим (в проде это делает nginx) |
| `--serve-downloads` | отдавать `/dl/` самим (dev-режим) |
| `--listen URL` | адрес, только `http://127.0.0.1:PORT` |

## Развёртывание

Пошаговый план для Ubuntu: [`deploy/README.md`](deploy/README.md).

Первая выкладка занимает девять шагов (пакеты, образ хранилища, systemd, сертификат, пароль, nginx). Дальнейшие обновления делаются одной командой:

```sh
rm -f build/release/cloud && deploy/deploy.sh root@SERVER
```

Скрипт прогонит тесты, соберёт статический бинарник (`glibc-static` на машине сборки), загрузит его и перезапустит службу.

## Бэкапы

- **На сервере**: systemd-таймер в 03:30 делает снимок через [restic](https://restic.net), хранит 7 дневных и 2 недельных копии и запускает `restic check`.
- **На домашнем компьютере**: пользовательский таймер забирает репозиторий по rsync (pull) ограниченным ключом, который умеет только читать (`rrsync -ro`).
- Пароль restic хранится вне сервера, без него копии не прочитать.

Файлы лежат в [`deploy/backup/`](deploy/backup) и [`deploy/backup/fedora/`](deploy/backup/fedora).

## Безопасность

- Пути проверяются через `realpath`: `..`, симлинки наружу и соседние каталоги с общим префиксом отвергаются.
- Файловые операции идут через `openat`/`mkdirat`/`unlinkat` с `O_NOFOLLOW`.
- Файлы создаются с правами `0640`, папки `0750`, nginx читает их через группу `cloud`.
- Служба работает под отдельным пользователем в песочнице systemd (`ProtectSystem=strict`, `NoNewPrivileges`, лимит памяти).
- Самоподписанный сертификат: при первом входе сверяйте отпечаток, при смене IP сертификат нужно пересоздать.
