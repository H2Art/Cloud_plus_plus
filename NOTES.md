## Цель и ограничения
Личное облачное хранилище для одного пользователя (документы, до 2 ГБ): загрузка, скачивание, папки, удаление.
Сервер: HostVDS-1 (1 vCPU, 1 ГБ RAM, диск 10 ГБ, свободно ~6.7 ГБ), Ubuntu. Домена нет, платить за него не хочет.
Бэкапы раз в сутки: restic на сервере в /srv/backup, домашний Fedora сам забирает rsync (pull), когда включён.
Репозиторий: GitHub, приватный (Cloud_plus_plus).

## Стек и архитектура
Браузер -> nginx (HTTPS самоподписанный на IP, 10 лет; basic auth; /dl/ и /static/ отдаёт сам)
-> C-бэкенд (Mongoose 7.24, vendored в src/vendor) на 127.0.0.1:8080 (другой адрес main.c не примет).
Без БД, обычная ФС: loop-образ ext4 на 2 ГБ (`mkfs.ext4 -m 0`) смонтирован в /srv/storage, данные в /srv/storage/files.
Фронт: htmx 2.x (static/htmx.min.js, версия 4.x отвергнута: ответы 4xx/5xx подставляются, события переименованы) + app.js.
Docker не используем: systemd-юнит, статический бинарник (`make build LDFLAGS=-static`).

## Структура
```
src/core/   path, html, url, listing, quota, fileops, upload, cleanup   (без HTTP, не зависят от http/ и vendor/)
src/http/   api.c (маршруты, чистая логика), ups.c (поток загрузки), limits.h, mg_server.c (склейка с Mongoose)
src/main.c, src/vendor/mongoose.{c,h}, static/{app.js,app.css,htmx.min.js}
tests/core, tests/http, tests/js (node), tests/test.h (свой мини-фреймворк CHECK/DONE)
deploy/     README.md (пошаговый план), setup-server.sh, deploy.sh, systemd/cloud.service, nginx/cloud.conf
```
Makefile: `.RECIPEPREFIX := >`, флаги `-std=c11 -D_XOPEN_SOURCE=700 -Werror` + ASan/UBSan для тестов. Файлы `src/http/mg_*.c`
не входят в тесты. Новые модули и тесты подхватываются сами (wildcard). `make test`, `make build`.
Если `node` нет, JS-тесты пропускаются.

## Ключевые решения
- path_resolve: запрет `..`, realpath, проверка границы корня (root2 не проходит как root), симлинки наружу и битые отвергаются.
- fileops: родитель открывается и канонизируется, дальше openat/mkdirat/unlinkat с O_NOFOLLOW (удаление симлинка не трогает цель).
  Права: файлы 0640, папки 0750 (nginx читает через группу cloud: `usermod -aG cloud www-data`), в main `umask(027)`.
- Загрузка: `POST /upcheck?p&size` (предпроверка, понятные коды 400/403/404/409/413/507), затем `PUT /up?p=` через
  mg_http_stream_body. Данные идут в скрытый `.part-<pid>-<n>`, публикация только при ровно Content-Length байт
  (link+unlink, без перезаписи существующих). Mongoose при отказе внутри потока всегда отвечает 500 "0 fail", отсюда /upcheck.
  Колбэк потока: data!=NULL порция; hm и не начат: старт; иначе конец (ровно один раз, там освобождается ctx).
- Лимиты: файл до 500 МБ (= client_max_body_size 500m), резерв диска 1 МБ. Перезапись существующих файлов запрещена.
- Защита от CSRF: изменяющие запросы требуют заголовок `HX-Request: true`. Ответы с CSP, nosniff, no-store.
- Маршруты: GET `/`, GET `/list?p=`, POST `/mkdir` (dir, name), DELETE `/rm?p=`, POST `/upcheck`, PUT `/up`.
- Временные `.part-*` скрыты в списке, недоступны через API, nginx их не отдаёт, при старте main чистит оставшиеся.
- Dev-режим бэкенда: `--static DIR`, `--serve-downloads` (в проде это делает nginx).

## Статус

список, создание/удаление папок, загрузка (мелкая, 5 МБ побайтово, пустой файл, обрыв без мусора), отказы, скачивание в dev-режиме,
страницу в браузере. Фиолетовый редизайн с белым акцентом и drag&drop сделан, отзыв пользователя был положительным.
